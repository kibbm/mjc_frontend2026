화장실의 기본 조건

  • 학교 화장실에는 독립된 칸이 3개 있습니다.
  • 학생 7명이 화장실을 이용하려고 합니다.
  • 한 칸에는 한 명만 들어갈 수 있습니다.

  • 휴지 보관함과 사용 가능 여부를 표시하는 장치가 있습니다.

03 · 문맥교환 (Context Switching)

관리 직원이 청소에서 휴지 보충 업무로 이동

단일 CPU 코어는 같은 순간에 하나의 실행 흐름만 처리합니다.

문맥교환의 정의

CPU가 현재 실행 중인 프로세스 또는 스레드의 실행 문맥을 저장하고, 다른 프로세스 또는 스레드의 실행 문맥을 복원하여 실행을 전환하는 과정입니다.

관리 직원의 세 가지 업무

  • P1: 첫 번째 화장실 청소
  • P2: 두 번째 화장실 휴지 보충
  • P3: 세 번째 화장실 시설 점검

P1 청소가 40% 진행되었을 때 P2의 휴지가 떨어졌다는 연락이 오면, P1 진행 상황을 기록한 후 P2로 이동합니다. 나중에 P1으로 돌아오면 기록된 시점부터 이어서 작업할 수 있습니다.

교수자가 강조할 설명

저장과 복원에는 시간이 소요되며, 문맥교환 자체는 사용자 프로그램의 연산 결과를 만들어내지 않습니다.

07 · 상호배제 (Mutual Exclusion)

화장실 한 칸에 두 사람이 동시에 들어갈 수 없습니다

임계구역(Critical Section)에 대한 배타적 접근을 보장하는 문제입니다.

상호배제의 정의

두 개 이상의 프로세스 또는 스레드가 동일한 공유 자원의 임계구역에 동시에 진입하지 못하도록 제한하는 원리입니다.

화장실 비유

학생 A와 학생 B가 동시에 한 칸 앞에 도착했습니다. 잠금장치가 없다면 두 사람 모두 빈 화장실이라고 판단하고 동시에 문을 열려고 할 수 있습니다.

잠금장치를 사용하면 먼저 입장한 학생만 이용할 수 있고, 다른 학생은 문이 열릴 때까지 대기해야 합니다.

경쟁 상태(Race Condition)는 실행 순서에 따라 공유 자원의 결과가 달라질 수 있는 문제입니다.

잠금 동작의 5단계

  1. 학생 A가 문을 잠금 → Lock
  2. A가 화장실 사용 → Critical Section
  3. 학생 B는 문 앞 대기 → Waiting
  4. A가 문을 열고 퇴장 → Unlock
  5. B가 잠금 획득 후 이용 → Lock

상호배제는 CRITICAL_SECTION으로 구현할 수 있습니다

화장실 잠금·이용·잠금 해제의 순서를 Windows API에 대응합니다.

실제 프로그래밍 적용

EnterCriticalSection()은 잠금 획득 후 임계구역에 진입하는 동작입니다. LeaveCriticalSection()은 잠금을 해제하여 다른 스레드가 접근할 수 있게 합니다.

// 임계구역 진입: 화장실 문 잠금
EnterCriticalSection(&cs);

// 공유 자원을 사용하는 임계구역
sharedCount++;

// 임계구역 이탈: 잠금 해제
LeaveCriticalSection(&cs);

주의 사항

잠금을 사용하더라도 초기화, 예외 경로, 잠금 해제 위치가 정확해야 합니다. 임계구역 내부의 읽기·수정·쓰기 전체를 보호해야 갱신 손실을 막을 수 있습니다.

11 · 세마포어 (Semaphore)

화장실 칸이 3개라면 동시에 최대 3명 이용

잠금장치 하나가 아니라, 사용 가능한 자원의 개수를 관리합니다.

세마포어의 정의

사용 가능한 자원 허가 수를 관리하거나 작업 간 실행 순서를 조정하는 동기화 기법입니다.

S = 3초기값 = 사용 가능한 화장실 칸 수
동시에 이용할 수 있는 최대 인원 = 3명

원자적 연산 두 가지

P(wait) 사용 허가를 획득합니다. 허가가 없으면 기다립니다.

V(signal) 사용 허가를 반환하고 필요하면 기다리는 작업을 깨웁니다.

화장실에 한 명이 들어가면 허가 하나를 획득하고, 나가면 다시 반환합니다.

13 · 세마포어의 Windows C 구현

CreateSemaphore로 허가 3개를 생성합니다

동시에 접근 가능한 공유 자원 개수를 3개로 제한하는 예제입니다.

// 초기 허가 3개, 최대 3개
HANDLE semaphore = CreateSemaphoreA(
    NULL, 3, 3, NULL
);

// P(wait): 허가 획득
WaitForSingleObject(
    semaphore, INFINITE
);

// 화장실 이용(공유 자원 사용)
Sleep(1000);

// V(signal): 허가 반납
ReleaseSemaphore(
    semaphore, 1, NULL
);

학생 행동사용 중S 값
처음0명3

학생 2 입장2명1
학생 3 입장3명0

* 대기자에게 바로 허가가 전달되는 순간의 논리적 설명입니다. 실제 API 내부 카운트와 스케줄링 시점은 구현에 따라 다릅니다.

14 · 동기화 문제 (Synchronization)

휴지가 준비되어야 화장실 이용자가 가져갈 수 있습니다

여러 작업이 공유 자원에 접근하는 순서와 조건을 조정합니다.

동기화의 정의

여러 프로세스·스레드가 공유 자원을 올바르게 사용하고 필요한 작업을 정해진 선후 관계에 따라 실행하도록 조정하는 것입니다.

생산자–소비자 문제

  • 생산자: 관리 직원이 휴지를 보충합니다.
  • 소비자: 학생이 휴지를 가져갑니다.
  • 공유 버퍼: 휴지 3개까지 담을 수 있는 보관함입니다.
휴지가 하나도 없으면 소비자는 기다려야 하고, 보관함이 가득 차면 생산자는 빈 공간이 생길 때까지 기다려야 합니다.

휴지 보관함(3개)의 empty와 full을 관찰하세요

휴지 보충은 생산, 휴지 사용은 소비입니다. 버퍼가 비거나 가득 찼을 때의 제한을 확인합니다.

그림 4. 공유 버퍼 · 휴지 보관함

empty3
full0
mutex*1

생산자(관리 직원)

휴지 보충 보관함에 빈 공간이 있을 때만 휴지를 추가할 수 있습니다.

버퍼가 가득 찼을 때는 생산자가 대기해야 합니다.

소비자(학생)

휴지 사용 보관함에 휴지가 있을 때만 가져갈 수 있습니다.

버퍼가 비었을 때는 소비자가 대기해야 합니다.

처음에는 휴지가 없는 상태입니다. 휴지 보충 버튼을 눌러 시작하십시오.

* mutex는 각 보충·사용 작업의 임계구역 진입 시 0, 이탈 후 1이 되는 상태를 단순화했습니다. 버튼 사이에는 1로 표시합니다.

버튼 비활성화는 실제 세마포어의 대기 상태를 시각적으로 단순화한 것입니다.16 / 22
16 · 세마포어 3개의 역할

empty · full · mutex가 함께 작업을 안전하게 조정합니다

생산자–소비자 문제에서는 자원 수 제한과 상호배제 모두 필요합니다.

세마포어초기값기능
empty3비어 있는 휴지 보관 공간 수
full0가져갈 수 있는 휴지 수
mutex1보관함 갱신 시 상호배제

생산자 · 관리 직원

  1. P(empty) → 빈 공간 확보
  2. P(mutex) → 보관함 잠금
  3. 휴지 1개 보충
  4. V(mutex) → 잠금 해제
  5. V(full) → 사용 가능 알림

소비자 · 학생

  1. P(full) → 휴지 확보
  2. P(mutex) → 보관함 잠금
  3. 휴지 1개 사용
  4. V(mutex) → 잠금 해제
  5. V(empty) → 빈 공간 알림
핵심: empty와 full은 작업 순서와 버퍼 상태를 동기화하고, mutex는 공유 보관함 접근을 상호배제합니다.

17 · 동기화 문제 ① 교착상태

서로가 가진 열쇠를 기다리면 아무도 진행하지 못합니다

교착상태(Deadlock): 여러 작업이 서로의 자원 반납을 기다리며 진행하지 못하는 상태입니다.

화장실 열쇠와 휴지 창고 열쇠

직원 A는 화장실 열쇠를 가지고 휴지 창고 열쇠를 기다립니다. 직원 B는 휴지 창고 열쇠를 가지고 화장실 열쇠를 기다립니다.

그림 5. 교착상태의 순환 대기

직원 A

화장실 열쇠 보유
창고 열쇠 대기

⇄
직원 B

창고 열쇠 보유
화장실 열쇠 대기

교착상태의 핵심

두 직원이 필요한 자원을 확보하지 못한 채 보유 중인 자원을 반납하지 않는다면, 두 업무는 계속 진행하지 못합니다.

  • 한 작업이 자원 A를 점유한 채 자원 B를 기다림
  • 다른 작업이 자원 B를 점유한 채 자원 A를 기다림
  • 상호 자원 대기로 실행이 멈춤

18 · 동기화 문제 ② 기아

줄은 서 있지만 우선순위에 계속 밀리면?

기아(Starvation): 특정 작업이 CPU 또는 자원을 오랫동안, 또는 무기한 할당받지 못할 수 있는 상태입니다.

학교 화장실 대기열 상황

학생 A가 오래 기다리고 있는데, 우선순위가 더 높은 새로운 이용자가 계속 먼저 들어오면 A의 대기 시간이 계속 길어질 수 있습니다.

그림 6. 우선순위에 따른 기아 발생

A · 오래 대기B · 높은 우선순위C · 높은 우선순위D · 높은 우선순위

새로운 높은 우선순위 이용자가 계속 먼저 입장 → A에게 차례가 오지 않을 가능성

교착상태와 기아의 차이

교착상태: 관련 작업들이 서로를 기다려 진행하지 못합니다.

기아: 다른 작업들은 진행하지만 특정 작업이 계속 배제될 수 있습니다.

FIFO 대기 정책이나 적절한 공정성 정책은 기아를 줄이는 데 도움이 될 수 있습니다.

화장실 사례를 통해 운영체제 원리를 설명해 보세요

질문을 선택하여 정답과 설명을 확인하십시오.

Q1. 누가 CPU를 사용하는지 바뀌는 과정은?

문맥교환입니다. 현재 실행 문맥을 저장하고 다른 문맥을 복원합니다.

Q2. 한 칸에 동시에 두 명이 들어오지 못하도록 하는 원리는?

상호배제입니다. 잠금으로 임계구역 동시 진입을 방지합니다.

Q3. 화장실이 3칸일 때 최대 이용자 3명을 제어하는 기법은?

카운팅 세마포어입니다. 초기 허가 S=3을 관리합니다.

Q4. 휴지가 없으면 기다리고, 준비되면 가져가게 하는 원리는?

동기화입니다. full/empty와 상호배제를 통해 생산·소비 순서를 조정합니다.

최종 정리: CPU의 교대 실행 → 자원의 독점 보호 → 여러 허가의 관리 → 작업 순서의 조율로 연결하여 이해합니다.
