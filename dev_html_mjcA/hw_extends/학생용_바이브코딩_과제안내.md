# 내 관심사로 만드는 jQuery 인터랙티브 페이지

제공된 `js+CSS+HTML.html`을 출발점으로, 자신이 관심 있는 주제의 웹페이지를 만듭니다. AI와 대화하면서 코드를 발전시키되, 직접 실행하고 수정한 내용을 자신의 말로 설명하는 것이 과제의 목표입니다.

## 제공 예제: 나만의 게임 추천 보드

완성 예제는 `game-recommendation-board.html`입니다. 원본의 헤더, 드롭다운 메뉴, 본문, 사이드바, 푸터 구조를 게임 추천 페이지로 발전시켰습니다. 게임 정보는 수업용 가상 데이터입니다.

HTML 파일을 브라우저에서 열어 실행합니다. 원본과 같은 jQuery 3.6.4 CDN을 사용하므로 인터넷 연결이 필요합니다. 추가한 게임과 찜 상태는 새로고침하면 초기화됩니다.

| 사용자 행동                    | 적용한 이벤트 | 예제의 선택자          | 화면에서 확인할 결과 |
| ---                           | ---          | ---                   | --- |
| 게임의 찜 버튼 누르기           | `click`      | `#main-section`에 위임, 대상 `.favorite-button` | 찜 상태와 찜 개수가 바뀐다. |
| 검색어 입력·삭제·붙여넣기       | `input`      | `#search-input`        | 검색어와 맞는 게임 목록으로 바뀐다. |
| 장르 선택 바꾸기               | `change`     | `#genre-filter`        | 선택한 장르에 맞게 목록이 바뀐다. |
| 추천 게임 추가 양식 제출하기    | `submit`     | `#recommend-form`      | 입력을 검사하고 새 게임을 목록에 추가한다. |
| 상단 메뉴에 포인터 올리고 내리기 | 원본의 `hover()` | `.outer-menu-item` | 하위 메뉴가 열리고 닫힌다. |

기존 `hover()` 기능에 더해 **서로 다른 이벤트 종류 4개**를 추가한 예제입니다. 학생 과제의 최소 조건은 서로 다른 이벤트 종류 3개 이상입니다. 여러 버튼에 `click`을 넣어도 이벤트 종류는 1개로 셉니다. 원본의 `hover()`만 재사용한 것은 추가 개수에 포함하지 않습니다.

`$(document).ready(...)`는 초기 실행 준비를 위한 코드이므로 이번 과제의 사용자 이벤트 개수에서 제외합니다. `.show()`, `.hide()`, `.text()`, `.val()`, `.toggleClass()`는 요소를 읽거나 바꾸는 메서드이며 이벤트 이름이 아닙니다.

## 개인 과제 조건

1. 자신이 관심 있는 주제와 이 페이지를 사용할 사람을 정합니다. 게임, 음악, 운동, 반려동물, 여행, 책, 음식 등에서 자유롭게 선택합니다.
2. 원본의 주요 구조를 활용하고 제목, 메뉴, 본문, 사이드바를 주제에 맞게 바꿉니다. 색상과 글자만 바꾸지 말고 콘텐츠와 기능도 개인화합니다.
3. 주제와 연결되는 **서로 다른 jQuery 이벤트 종류를 3개 이상 추가**합니다. 각 기능은 실제 화면 변화나 입력 처리 결과가 있어야 합니다.
4. 이벤트 등록은 `.on('이벤트이름', function (...) { ... })` 형식을 사용합니다. 처리 대상 선택자와 이벤트 처리 함수를 설명할 수 있어야 합니다.
5. 입력값을 받는 기능은 빈 값과 잘못된 입력을 확인합니다. 사용자가 쓴 글은 실행 가능한 HTML이 되지 않도록 텍스트로 표시합니다.
6. AI가 만든 코드를 직접 실행하고, 수정·검증 과정을 기록합니다. 이해하지 못한 코드는 설명을 요청하고 다시 확인합니다.

예를 들어 음악 주제라면 ‘검색어 입력(`input`) → 곡 찾기’, ‘분위기 선택(`change`) → 목록 분류’, ‘즐겨찾기 버튼(`click`) → 내 목록에 표시’를 연결할 수 있습니다. 이벤트 개수를 채우기 위해 주제와 관계없는 기능을 억지로 추가하지 않습니다.

## AI에 보낼 첫 프롬프트 예시

먼저 원본 `js+CSS+HTML.html`을 첨부하거나 코드 전체를 함께 제공합니다. 다음은 게임 주제를 선택한 학생이 사용할 수 있는 프롬프트입니다.

```text
첨부한 js+CSS+HTML.html을 기본으로 ‘나만의 게임 추천 보드’를 만들어 줘.
사용자는 게임을 검색하고, 장르로 걸러 보고, 마음에 드는 게임을 찜하고,
자신의 추천 게임을 추가하려는 사람이다.

[원본 활용]
- #page-wrapper, #main-header, #main-navigation, #content,
  #main-section, #main-aside, #main-footer 구조를 활용해 줘.
- 기존 드롭다운 메뉴와 hover 동작은 유지해 줘.
- HTML, CSS, JavaScript를 하나의 HTML 파일에 담아 줘.
- 원본과 같은 jQuery 3.6.4를 사용하고, 별도 프레임워크는 쓰지 마.
- UTF-8과 모바일 화면에 맞는 viewport 설정을 넣어 줘.

[주제와 기능]
- 수업용 가상 게임을 4개 이상 넣고 제목, 장르, 추천 이유를 표시해 줘.
- click: 찜 버튼을 누르면 찜 상태와 찜 개수가 바뀌게 해 줘.
- input: 검색어를 입력·삭제·붙여넣기할 때 목록을 바로 검색해 줘.
- change: 장르 select를 바꾸면 해당 장르의 게임만 보여 줘.
- submit: 제목·장르·추천 이유를 입력하고 제출하면 새 게임을 추가해 줘.
- 검색어와 장르 조건을 동시에 적용하고, 결과가 없으면 안내를 보여 줘.
- 새로 추가된 게임에서도 찜 버튼이 작동하도록 이벤트 위임을 사용해 줘.
- 빈 값이나 공백뿐인 값은 추가하지 않고, 이유를 화면에 알려 줘.
- 사용자 입력을 표시할 때는 .text() 등을 사용해 텍스트로 처리해 줘.
- 서버나 로그인 없이 브라우저에서 실행되게 해 줘.
- 새로고침하면 상태가 초기화된다는 안내를 표시해 줘.

[학습을 위한 설명]
- 이벤트는 .on()으로 등록하고, 각 이벤트 코드 위에 학습용 주석을 달아 줘.
- 코드 뒤에 ‘이벤트 / 선택자 / 사용자 행동 / 처리 과정 / 화면 변화’ 표를 써 줘.
- this, $(this), 선택자, .val(), .text(), .toggleClass(),
  event.preventDefault(), 이벤트 위임이 이 코드에서 하는 일을 설명해 줘.
- 정상 동작, 빈 입력, 검색 결과 없음, 추가 후 찜하기를 확인할 순서를 알려 줘.
- 입문자가 이해할 수 있게 작성하고, 전체 HTML 코드를 제공해 줘.
```

개인 주제로 바꿀 때에는 제목만 교체하지 말고, 사용자·콘텐츠·사용자 행동·화면 변화까지 함께 바꿉니다. 최소 3종의 이벤트를 정한 뒤 “왜 이 이벤트가 내 주제에 필요한가?”에 답해 봅니다.

## 코드를 발전시키는 후속 프롬프트

**동작을 이해할 때**

```text
내 코드에서 input 이벤트를 등록한 부분을 찾아 줘.
선택자가 가리키는 HTML 요소, 이벤트 발생 시점, .val()로 얻는 값,
검색 조건을 적용하는 과정, 화면을 바꾸는 코드를 순서대로 설명해 줘.
내 코드의 실제 줄을 인용하고, 내가 답할 수 있는 확인 질문 2개를 내 줘.
설명에 없는 기능을 추가하지는 마.
```

**오류를 수정할 때**

```text
현재 코드와 오류 상황을 함께 줄게.
재현 순서: [어떤 값을 입력하고 무엇을 눌렀는지]
기대 결과: [내가 원한 화면]
실제 결과: [현재 화면과 개발자 도구 오류 메시지]
가능한 원인을 코드에서 찾고, 필요한 부분만 수정해 줘.
수정 전후 코드와 수정 이유, 같은 오류가 사라졌는지 확인할 방법을 알려 줘.
```

**직접 바꾸고 검증할 때**

```text
내 페이지의 [이벤트/기능]을 [구체적인 새 동작]으로 바꾸려고 해.
먼저 내가 수정해야 할 선택자와 처리 함수의 위치를 알려 줘.
전체 정답을 바로 주기 전에 수정 방향과 힌트를 줘.
내가 수정한 코드를 보내면 동작과 설명이 맞는지 검토해 줘.
```

## 실행 확인과 제출물

예제에서는 다음 순서로 확인합니다. 개인 과제에서는 자신의 주제와 기능에 맞게 바꿉니다.

| 확인 항목 | 조작 | 기대 결과 |
| --- | --- | --- |
| 검색 | 실제 제목 일부 입력 후 전부 삭제 | 해당 게임이 보이고, 삭제하면 검색 조건이 해제된다. |
| 조건 조합 | 장르 선택 후 검색 | 장르와 검색어를 모두 만족하는 항목만 보인다. |
| 결과 없음 | 일치하지 않는 검색어 입력 | 빈 목록 안내가 나타난다. |
| 찜 전환 | 같은 게임의 찜 버튼을 두 번 누르기 | 추가 후 취소되며 찜 개수가 맞게 바뀐다. |
| 입력 확인 | 제목 또는 추천 이유에 공백만 입력하고 제출 | 게임이 추가되지 않고 안내가 나타난다. |
| 동적 요소 | 유효한 게임 추가 후 새 카드의 찜 버튼 누르기 | 새 게임이 추가되고 찜도 작동한다. |
| 입력 표시 | 제목에 `<b>테스트</b>` 입력 후 추가 | 태그가 실행되지 않고 입력한 글자가 그대로 보인다. |

제출할 자료는 다음과 같습니다.

- 실행 가능한 개인 HTML 파일과 주제·사용자·주요 기능 소개
- 실제로 사용한 첫 프롬프트와 의미 있는 수정 프롬프트
- 아래 양식으로 정리한 서로 다른 이벤트 3종 이상의 학습 기록
- 기능별 실행 결과 또는 화면 캡처와 오류 수정 사례 1개

## 개인별 jQuery 학습 기록 양식

아래 표를 이벤트 **종류별로** 복사하여 작성합니다. 자신의 최종 코드에 있는 선택자와 실제 코드 위치를 적습니다. AI 설명을 그대로 붙이지 말고 직접 조작한 결과와 연결해 설명합니다.

| 항목 | 내가 작성할 내용 |
| --- | --- |
| 개인 주제 / 기능 이름 | |
| 이벤트 이름과 선택 이유 | 이 행동에 이 이벤트가 적절한 이유는? |
| 이벤트가 발생하는 조건 | 사용자가 무엇을 해야 실행되는가? |
| 이벤트 등록 대상과 선택자 | 선택자가 내 HTML의 어떤 요소를 가리키는가? |
| 핵심 코드와 위치 | 파일명, 줄 번호, 실제 코드 3~10줄 |
| 처리 함수의 실행 순서 | 입력 읽기 → 조건 판단 → 데이터/요소 변경 순으로 설명 |
| 사용한 jQuery 메서드 | `.val()` 등의 역할과 반환값/변경 대상을 설명 |
| 변경되는 DOM 또는 상태 | 어떤 글자·클래스·목록·개수가 어떻게 바뀌는가? |
| 테스트 입력과 예상 결과 | 정상 사례와 예외 사례를 각각 작성 |
| 실제 결과와 확인 증거 | 직접 실행한 결과, 화면 캡처 또는 기록 |
| AI 코드의 오류·부족한 점 | 어떤 조건에서 문제가 생겼는가? |
| 내가 수정한 내용과 이유 | 수정 전후 코드와 재확인 결과 |

모든 이벤트에 `this`나 이벤트 위임이 필요한 것은 아닙니다. 사용한 경우에는 자신의 코드에서 그 역할을 설명하고, 사용하지 않은 경우에는 해당 없다고 적습니다. 수정 경험이 없는 기능에는 다른 기능에서 발견·수정한 사례를 연결할 수 있습니다.

## 기말 서술형 대비 문항 예시

**문항 1 — 내 코드의 동작 설명**

> 개인 과제에 추가한 서로 다른 jQuery 이벤트 3종을 골라, 각 이벤트의 필요성, 등록 대상 선택자, 발생 조건, 처리 함수, 화면 변화를 자신의 코드와 연결하여 설명하시오. 그중 한 기능은 실제 코드 3~10줄을 제시하고 실행 순서를 설명하시오. 이벤트와 DOM 변경 메서드를 구분하시오.

**문항 2 — 변경 상황과 오류 해결**

> 자신의 과제에서 동적으로 추가되는 요소 또는 입력을 처리하는 기능 하나를 고르시오. 직접 연결과 이벤트 위임의 차이 또는 `preventDefault()`의 필요성 중 해당 코드와 관련 있는 내용을 설명하시오. 이어 실제로 발견한 오류의 재현 조건, 원인, 수정 내용, 수정 후 확인 결과를 서술하시오.

문항 2의 개념은 자신의 구현과 관련 있는 것을 선택합니다. 예제에서 추천 추가 폼의 기본 제출을 막는 이유나 새 게임의 찜 버튼까지 처리하는 이유를 찾아보되, 시험에서는 자신의 기능을 근거로 답합니다. 최종 문항과 배점은 수업 공지에 따릅니다.

| 평가 기준 예시 | 확인할 내용 |
| --- | --- |
| 주제와 원본 활용 | 관심 주제가 콘텐츠·기능에 반영되고 기본 구조를 활용했는가? |
| 이벤트 구현 | 서로 다른 추가 이벤트 3종 이상이 의도대로 작동하는가? |
| 코드 이해 | 선택자, 이벤트, 처리 함수, jQuery 메서드, DOM 변화를 구분하는가? |
| 검증과 수정 | 정상·예외 상황을 실행하고 오류 원인과 수정 근거를 제시했는가? |
| 개인 학습 설명 | 자신의 실제 코드와 결과를 근거로 자기 말로 설명하는가? |

## 공식 문서로 확인하기

- [jQuery `.on()`과 이벤트 위임](https://api.jquery.com/on/): 이벤트 등록과 동적으로 추가되는 하위 요소의 처리 방법
- [jQuery `change` 이벤트](https://api.jquery.com/change/): select 변경과 텍스트 입력의 변경 시점
- [jQuery `submit` 이벤트](https://api.jquery.com/submit/): 폼 제출 처리
- [jQuery `event.preventDefault()`](https://api.jquery.com/event.preventDefault/): 폼 제출 등 브라우저 기본 동작 방지
